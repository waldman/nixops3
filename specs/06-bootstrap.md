# Bootstrap — Golden ISO and First Boot

## Machine Identity

Each machine has two identifiers:

| Identifier | Source | Survives Reinstall | Purpose |
|------------|--------|--------------------|---------|
| `hostname` | `/proc/sys/kernel/hostname` | Yes (if set in NixOS config) | S3 path lookup, DynamoDB PK |
| `machine_id` | `/etc/machine-id` | No | DynamoDB deduplication |

`/etc/machine-id` is generated by systemd on first boot and persists across reboots. It changes on OS reinstall. This is acceptable — the `hostname` is the durable identity.

## Golden ISO

The Golden ISO is a NixOS installer image that performs an unattended installation. It embeds:

- The `nixops3` binary
- `/etc/nixops3/nixops3.toml` with the S3 bucket and credentials pre-configured
- A role assignment (`role = "..."` in the config)

The ISO does **not** embed a `machine_id`. Identity is established on first boot by the OS.

### ISO Build

The ISO is built from a NixOS installer configuration that adds a systemd `oneshot` service running an auto-install script:

```
Pseudo-steps of auto-install script:
1. Wait for network (systemd-networkd-wait-online)
2. Detect primary disk (largest block device, or configured via kernel cmdline)
3. Partition: 512MB ESP + remainder root (ext4)
4. Mount at /mnt
5. nixos-generate-config --root /mnt
6. Copy /etc/nixops3/nixops3.toml to /mnt/etc/nixops3/
7. Copy ada-server/configuration.nix to /mnt/etc/nixos/
8. nixos-install --no-root-passwd
9. Print IP address to console/serial
10. Reboot
```

The installed system boots with `nixops3` enabled. On first poll, it fetches and applies its full configuration from S3.

### Role-Specific ISOs

A single ISO may target one role (e.g., `home/production/ada`) or be generic (role configured at install time via kernel cmdline `nixops3.role=home/production/ada`).

For v1: role is hardcoded in the ISO. One ISO per role is acceptable at small fleet sizes.

## First Boot Sequence

1. Systemd starts `nixops3.service` (ExecStart is `nixops3 --daemon`)
2. `nixops3` reads `/etc/nixops3/nixops3.toml`
3. No `/var/lib/nixops3/current` symlink exists → apply immediately (no initial sleep)
4. GET `s3://<bucket>/current` → target sha
5. GET `commits/<sha>/roles/<role>/canary.txt` — 404 or hostname listed → proceed; else skip
6. List and parallel-fetch every object under `commits/<sha>/` → written to `/var/lib/nixops3/commits/<sha>/`
7. Fetch secrets from AWS Secrets Manager to `/run/nixops3/secrets/`
8. If `/etc/nixos/hardware-configuration.nix` is absent, run `nixos-generate-config`
9. Write `/etc/nixos/configuration.nix` (standard NixOS location — no `-I nixos-config` needed)
10. Run `nixos-rebuild switch -I nixops3=/var/lib/nixops3/commits/<sha> [-I nixpkgs=...]`
11. On success: atomically advance the `/var/lib/nixops3/current` symlink; write DynamoDB heartbeat
12. Enter normal poll loop

## Cloud-init (VM Deployments)

For VMs, the Golden ISO is replaced by a base NixOS image + cloud-init. The cloud-init `write_files` directive installs `/etc/nixops3/nixops3.toml` with the correct role and credentials. The daemon then handles the rest on first boot.

Example cloud-init fragment:

```yaml
write_files:
  - path: /etc/nixops3/nixops3.toml
    permissions: '0600'
    owner: root:root
    content: |
      bucket = "nixops3-waldman"
      region = "us-east-1"
      role   = "home/production/ada"

      [aws]
      access_key_id     = "AKIA..."
      secret_access_key = "..."

      [inventory]
      enabled = true
      table   = "nixops3-inventory"

runcmd:
  - systemctl enable --now nixops3
```

## Security Considerations

- The Golden ISO contains AWS credentials. Treat ISO files as sensitive. Do not publish or share them.
- For EC2 instances, use IAM instance roles instead of embedding credentials — omit the `[aws]` section from `nixops3.toml`.
- The `/etc/nixops3/nixops3.toml` file must be mode `0600`, owner `root:root`.
